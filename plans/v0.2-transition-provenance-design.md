# v0.2 transition and provenance design

Status: implemented on `feat/v0.2-safety-provenance`; release/tag not published.

## Goals

1. Prevent a stale panel, retry, or generic phase control from rewinding or completing the wrong attempt.
2. Make every terminal result traceable to the child work that produced it.
3. Preserve append-only migration compatibility with v0.1.x data.
4. Keep Standard Harness operator-driven and bounded rather than turning it into a workflow engine.

## State authority

- `arcs.plan_id` identifies the run owned by a parent thread.
- `plans.lifecycle` is one of `active`, `completed`, `cancelled`, `superseded`, or `archived`.
- A partial unique index permits at most one `active` plan per thread.
- `plans.revision` is the optimistic-concurrency authority for mutations.
- `plan_nodes.revision` records local node evolution.
- The normal displayed phase is projected from the active node or next ready DAG node. Stored phase overrides remain recovery metadata only.

A transition request supplies `expectedRevision` and `requestId`. The server serializes parent-thread lifecycle operations and rejects a revision mismatch before mutating state.

## Normal transitions

- **Start** claims one pending node before any asynchronous spawn.
- **Child attach** records the child and attempt immediately after spawn.
- **Complete** requires `in_progress`, the current attempt ID, real non-empty child output, and an operator summary or artifact reference for child execution.
- **Critic REWORK** requires a summary and correction capacity, records the exact Critic output, stops the Critic child, increments corrections, and resets the latest completed Worker plus Critic atomically.
- **BLOCK reset** requires an audit reason.
- **Stop** is cancellation: live children become interrupted, active nodes settle, the plan becomes `cancelled`, and the arc is removed.
- When all nodes are done or skipped, the plan becomes `completed` and the arc is removed.

Generic `advance` and `rewind` reject mutation. Worker reopen and phase set are explicit recovery operations with mandatory reasons.

## Attempt and result provenance

`plan_node_attempts` records:

- child thread, provider/model source, timestamps, duration, and token counters;
- terminal outcome: `running`, `idle_with_output`, `idle_empty`, `failed`, `interrupted`, or `stopped`;
- SHA-256 of normalized child output when available.

`plan_node_results` binds:

- `attempt_id`;
- `child_thread_id`;
- `output_hash`;
- `request_id`;
- `expected_revision`;
- verdict, summary, artifacts, actor, source, and time.

`thread.idle` uses BB's `lastAssistantText` to classify empty versus output-bearing attempts. Completion also reads the durable child output endpoint before accepting a child result.

## Mutation ledger

`plan_mutations` is append-only and records action, actor, source, request, reason, expected/resulting revisions, attempt/child/output references, details, and time. Covered actions include run start/stop/supersede, node start, child attach, completion, Critic REWORK, skip, routing changes, node addition, block reset, failed-child reconciliation, and legacy/recovery operations.

Full plan reads expose up to 100 recent mutations. Agent mutation tools return compact deltas instead of echoing full attempts/results.

## Permissions and trust

Worker children inherit normal BB execution permissions. Critic and Promote request the least-privileged available BB mode, `accept-edits`. This is defense in depth, not a sandbox. BB plugins and provider sessions remain trusted local code; canonical parent/project ownership and operator review prevent accidental misuse.

## Migration

Migrations only append columns, tables, indexes, and conservative data normalization. Existing plans default to `archived`; the plan referenced by an arc is promoted to `active`; already-terminal active plans become `completed` and their stale arcs are removed. Legacy result provenance remains explicitly `legacy`/unknown rather than invented.

## Verification matrix

- stale revision rejection;
- empty child output rejection;
- accepted result-to-attempt/output-hash binding;
- Critic REWORK and correction limits;
- generic rewind rejection;
- Start/Stop and duplicate Start races;
- failed/idle attempt outcome reconciliation;
- explicit `--thread` CLI authority;
- local database append-only migration and reload;
- UI Stop confirmation with revision provenance.
